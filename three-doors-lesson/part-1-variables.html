A story needs to remember what the player has done. Start by tracing what a variable stores, then decide where to declare it.

1. A variable stores a value

A declaration introduces a variable and its type. An assignment stores a value. In int score = 0;, we do both.

int a = 5;
int b = a;
a = 3;

Read assignment from right to left: evaluate the expression on the right, then store the result in the variable on the left. b = a copies the current integer value of a. It does not link the two variables.

= assigns a value. == compares values and produces true or false.

Try it

Draw a snapshot after every line. Do this on paper before running it.

int keys = 1;
int savedKeys = keys;
keys = keys + 2;
savedKeys = savedKeys + 1;
Check your reasoning

After each line: keys=1; then keys=1, savedKeys=1; then keys=3, savedKeys=1; finally keys=3, savedKeys=2. The right side of keys = keys + 2 uses the old value before replacing it.

3. Where can a variable be used?

Scope is the region of code where a variable name can be used. Lifetime concerns how long its storage exists during execution. These are related ideas, but they answer different questions.

Declaration locationWhere you can use it in our sketchesWhat happens between calls
Outside all functions: globalThroughout the sketch, unless a local variable hides its nameIts value remains until code changes it or the sketch ends.
Inside a function: localFrom its declaration through the rest of its enclosing blockEach function call has its own local variables.
Inside an if block: localFrom its declaration to that block’s closing braceIt belongs to that execution of the block.
void setup() {
  size(400, 200);
  int secret = 7;
  println(secret); // Allowed here.
}

void draw() {
  // println(secret); // Not allowed: secret is local to setup().
}

A local variable declared inside an if block cannot be used after that block’s closing brace, even if the block ran. This applies in Processing’s Java mode.

4. What survives the next frame?

int total = 0;

void setup() {
  size(400, 200);
  frameRate(1);
}

void draw() {
  int count = 0;
  total = total + 1;
  count = count + 1;
  println("total: " + total + ", count: " + count);
}

Try it

Predict the first three lines printed. Identify the global and local variables. Then run the sketch.

Check your reasoning

The output is total: 1, count: 1, then total: 2, count: 1, then total: 3, count: 1. Each call to draw() executes int count = 0; again. The global total keeps its updated value.

After the first call: global box total [1]; that call’s local box count [1] ends with the call. During the next call, a new local count starts at 0.

Be careful: a global variable can still be reset every frame if you put an assignment such as total = 0; inside draw(). Declaration location and the statements that run both matter.

Extra prediction: two variables with the same name

Predict what setup() prints and what draw() prints. Explain which variable each function uses.

int room = 0;

void setup() {
  int room = 1;
  println(room);
}

void draw() {
  println(room);
}
Check your reasoning

setup() prints 1. draw() repeatedly prints 0. The local declaration creates a separate variable that hides, or shadows, the global name inside setup(). Removing int from int room = 1; makes it an assignment to the global variable.

5. Remember a room

The program’s state is the information that describes its current situation. We will use room = 0 for the start and room = 1 for the library.

int room = 0;

void setup() {
  size(600, 400);
  textSize(24);
}

void draw() {
  if (room == 0) {
    background(230);
    fill(0);
    text("Start: click to enter", 40, 60);
  } else if (room == 1) {
    background(30, 60, 90);
    fill(255);
    text("You found the library.", 40, 60);
  }
}

void mousePressed() {
  room = 1;
}

draw() reads the state to choose a screen. Processing calls mousePressed() when you press a mouse button; this function changes the state.

Try it

  1. Run the sketch and click once.
  2. Draw the global room box before the click, after the click, and during the next frame.
  3. Explain why declaring room inside setup() would not work.
  4. Predict what would happen if room = 0; were the first statement in draw().
Check your reasoning

The snapshots are 0 → 1 → 1. A variable local to setup() is inaccessible in the other functions. Resetting the global to 0 in every draw() call would keep drawing the start screen.
