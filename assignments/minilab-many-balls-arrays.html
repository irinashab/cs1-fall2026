Mini-Lab: Many Bouncing Balls (Arrays)

Purpose

You already know how to animate a single bouncing ball using individual variables. In this mini-lab you will animate many balls by replacing those variables with arrays. This is your first step toward managing multiple moving objects.

Reference: single bouncing ball (from the earlier lab)

Show the single-ball sketch 
float xspeed, yspeed;
float xpos, ypos, wdth, ht;

void setup(){
  size(1000, 1000);
  background(0);

  xpos = random(width);
  ypos = random(height);
  xspeed = random(3);
  yspeed = random(3);

  wdth = random(20);
  ht = wdth;

  noStroke();
}

void draw(){
  background(0);
  ellipse(xpos, ypos, wdth, ht);

  xpos += xspeed;
  ypos += yspeed;

  if (xpos >= width || xpos <= 0){
    xspeed *= -1;
  }
  if (ypos >= height || ypos <= 0){
    yspeed *= -1;
  }
}

Note: the bounce in this reference treats the ball as a point. Once balls have a visible size, that logic is no longer correct. You will fix this below.

Instructions

  1. Choose the number of balls. Declare an integer variable n and give it a value around 20. This value determines both how many balls you draw and the length of every array you create.
  2. Turn each ball property into an array. Look at the single-ball sketch. Every variable that describes the ball — position, speed, size — becomes an array of length n. Declare those arrays at the top of your sketch.
  3. Initialize all balls in setup(). Use a loop so that each index i represents one ball. Choose speeds and sizes that give you a visually interesting variety — for example, let the speed or size depend on i.
  4. Print the endpoints of your arrays in setup(). Print xpos[0] and xpos[n - 1], and print wdth[0] and wdth[n - 1]. These two lines let you confirm that your indexing is correct before anything starts moving.
  5. Make ball 0 start off-screen. After initializing the arrays, set the x-position of ball 0 to a value slightly to the left of the canvas. Ball 0 must still appear and bounce normally once the sketch runs.
  6. Animate all balls in draw(). Use a loop to draw each ball, update each ball's position, and handle bouncing. Every ball must be updated inside the same loop.
  7. Make the bounce respect ball size. A ball should reverse direction when the edge of the ball reaches the wall, not when its center does. Balls should never disappear partway off-screen.
  8. Do not call random() inside draw(). All randomness belongs in setup(). If a ball's speed or position changes every frame, you have a bug, not a feature.
  9. Try different values of n. Run your sketch with roughly 100, 1000, and 10000 balls. Write two or three sentences as a comment in your sketch describing what you observe as n grows.

Submission

  • Your sketch must run without errors and must include the two endpoint prints and the scalability comment.
  • Compress (zip) the sketch folder and submit the single .zip file.
