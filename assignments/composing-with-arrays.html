Composing with Arrays

Purpose

You have practiced arrays on lists of numbers and on bouncing balls. This assignment asks you to use arrays for something less obvious: music.

A melody is a sequence of pitches. A chord is several pitches at once. A canon is the same melody played twice with an offset in time. All of these are naturally represented as arrays, and representing them well is the hard part of this assignment. The code that plays them is the easy part.

You will write a short piece in Processing using Sound (or another library, if you prefer — see the note under Submission). The piece itself is up to you. What is not up to you is that the piece must be built from arrays in specific, named ways, and you must be able to explain which array technique is doing what.

What you must demonstrate

Choose three of the following six techniques. Each one is a real array pattern, not a trick. The musical idea next to each one is just an example of where it shows up.

  1. Parallel arrays for a melody. One array holds pitches, a second array holds durations. A single index walks both arrays together. Musical idea: a monophonic melody.
  2. A two-dimensional array for chords. Rows are time steps, columns are voices (or the reverse). Musical idea: a chord progression, or a harmonized melody.
  3. Offset playback (canon or round). The same array is played more than once, with each voice starting at a different time or at a different transposition. Musical idea: a canon, a round, or a phase piece.
  4. A repeating pattern with variation. A rhythmic or melodic array repeats, but one element is modified between repetitions. Musical idea: a phrase with a turnaround, or a pattern that evolves.
  5. A lookup table (indirection). One array stores a scale, mode, or set of allowed pitches. A second array stores indices into the first. Musical idea: a melody constrained to a scale, where the melody is written as scale degrees rather than absolute pitches.
  6. Arrays as state (a walking index). A longer piece is stored in one array, and an integer tracks the current position as the piece plays. The position advances over time and can be reset or jumped. Musical idea: a piece with sections, repeats, or a coda.

Constraints

  • The piece must be roughly 30–60 seconds long. Longer is not better; it is just more typing.
  • Every technique you claim must be implemented with a loop that walks an array. If you cannot point to the loop, it does not count.
  • Do not call random() during playback. Any randomness belongs in setup(). If the piece sounds different every time you run it, you have a bug.
  • You may use Sound, or you may look up and use another Processing sound library if you prefer. If you use a different library, say so in your write-up and explain briefly why you chose it.
  • The piece must actually play when the sketch runs. A sketch that only prints note names is not a submission.

Write-up (required)

Submit a short write-up alongside the sketch. Half a page is plenty. It must contain:

  1. Technique map. For each of the three techniques you chose, name the arrays involved, name the loop that implements it, and describe in one or two sentences what musical decision that technique corresponds to.
  2. Representation choices. Explain how you decided to represent a note, a chord, and time. There is no single correct answer here; the point is that you made a choice and can defend it.
  3. Reflection. One paragraph on what was hard about representing music as arrays. What did the array structure make easy? What did it make awkward? For example, did fixed-length arrays force you to do something you would not have done musically?

Submission

  • One Processing sketch containing the piece.
  • One write-up (plain text, PDF, or a comment block at the top of the sketch — your choice).
  • Compress (zip) the sketch folder with the write-up inside it, and submit the single .zip file.
