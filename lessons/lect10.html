Lesson 10: Functions

You have used variables to store state, conditionals to make decisions, and loops to repeat work. Functions let you organize that work into named pieces that you can call when needed.

In this lesson, you will define functions, pass information through parameters, return results, and reorganize an existing sketch. The exercises are included below.

1. What is a function?

A function is a named block of code that performs a task. It can receive input through parameters and may return a value. Some functions draw, print, or change state instead of returning a result. In Processing’s Java mode, these functions are also methods.

You already know functions:

ExampleWhat it does
ellipse(100, 100, 30, 30)Draws a shape.
println(42)Prints to the console.
random(10)Returns a random floating-point value from 0 up to, but not including, 10.
setup() and draw()Functions that Processing calls as the sketch runs.

There are two reasons to define your own functions:

  • Modularity: divide a program into tasks that can be understood and tested separately.
  • Reusability: express a behavior once, then call it with different inputs instead of copying its code.

A loop repeats work. A function names a task. They can be used together.

2. Definition and call are different

This is a complete sketch:

void setup() {
  println("Before");
  printMessage();
  println("After");
}

void printMessage() {
  println("Inside the function");
}

Predict: In what order are the three messages printed?

Check your reasoning

Before → Inside the function → After. Execution reaches the call, runs printMessage(), then continues with the statement after the call.

void printMessage() { ... } is the definition. printMessage(); is a call. Writing a definition does not run it. Processing calls setup(), draw(), and event functions at the appropriate times; you decide where to call your own functions.

Define your functions outside setup(), draw(), and other function bodies. A definition can appear below the code that calls it. Its position on the page does not determine when it runs.

3. Read the function header

returnType functionName(parameterType parameterName, ...) {
  // body
}

This shows the structure; replace the placeholders with actual types and names. For example:

void drawEye(float x, float y, float diameter) {
  fill(255);
  ellipse(x, y, diameter, diameter);
  fill(0);
  ellipse(x + diameter * 0.15, y,
          diameter * 0.35, diameter * 0.35);
}
PartMeaning
voidThe function does not return a value.

The header includes the return type, name, and parameter list. In Java terminology, the signature is the name and ordered parameter types: drawEye(float, float, float). It does not include the return type or parameter names. See Java’s method definition reference.

4. Parameters receive the arguments from a call

Parameters are the variables declared in the definition. Arguments are the values supplied when calling it.

// Definition: x, y, and diameter are parameters.
void drawEye(float x, float y, float diameter) {
  fill(255);
  ellipse(x, y, diameter, diameter);
  fill(0);
  ellipse(x + diameter * 0.15, y,
          diameter * 0.35, diameter * 0.35);
}

void setup() {
  size(400, 300);
  background(200);
  drawEye(120, 140, 80);
  drawEye(250, 140, 50);
}

At the first call, the parameter values are x = 120, y = 140, and diameter = 80. The second call has its own parameter values: 250, 140, and 50. All positions and sizes inside the function are derived from those parameters, so the same definition draws both eyes.

Arguments are matched by position. Supply the right number in the intended order and with compatible types. An integer can be supplied to a float parameter through an automatic widening conversion; a float cannot generally be supplied to an int parameter without an explicit conversion. See Java’s parameter and argument reference.

An argument can be a literal, a variable, or an expression. These are example calls, assuming the referenced variables exist:

drawEye(120, 140, 80);
drawEye(mouseX, mouseY, 40);
drawEye(width / 2, height / 2, 20 + 30);

Predict: What would drawEye(80, 120, 140) change compared with the first call? The types still match, but the meaning of each argument changes because its position changes.

The eye function also changes the current fill color. Drawing settings such as fill persist after a function returns. Set the styles your drawing needs; a function call does not automatically restore them.

5. Parameters and local variables belong to a call

For primitive values such as int and float, the parameter receives a copy of the argument’s value. Assigning to the parameter does not assign to the caller’s variable.

void setup() {
  int a = 5;
  changeIt(a);
  println(a);
}

void changeIt(int n) {
  n = 999;
  println(n);
}

Draw separate memory boxes for a and n. Predict the output before expanding the explanation.

Check your reasoning
Momenta in setup()n in changeIt()
Before call5No active call
At function entry55
After n = 9995999
After return5Call has finished

The output is 999, then 5. Changing n changes the local copy. Each call gets its own parameters and local variables.

The caller cannot use a name local to the called function. A function can access global variables, but a parameterized function should use its parameters for the information it claims to receive.

For example, a function with a parameter named x will not respond properly to different x arguments if its calculation ignores x and always reads a global sqX.

6. A return value gives information back

A return value lets the caller use a result in an assignment, expression, or condition.

int bigger(int a, int b) {
  if (a > b) {
    return a;
  } else {
    return b;
  }
}

void setup() {
  int result = bigger(7, 12);
  println(result);
  println(bigger(20, 4) + 1);
}

The output is 12, then 21. The call bigger(7, 12) produces the value 12, which is stored in result.

return ends the current function call immediately and sends a value back when one is specified. A value-returning function must return a compatible value on every path that completes normally. A void function can use a bare return; to finish early, but cannot return a value.

Printing is different from returning

void printDouble(int n) {
  println(n * 2);
}

int doubleValue(int n) {
  return n * 2;
}

printDouble(6); prints 12. int result = doubleValue(6); stores 12 without printing it. You cannot assign the result of printDouble(6) to an int: its return type is void.

A returned value does not automatically change the argument you supplied:

int a = 5;
doubleValue(a);      // Calculates 10, but the result is discarded.
a = doubleValue(a);  // Stores the returned 10 in a.

This fragment belongs inside a function where doubleValue() is available.

7. Boolean functions separate checking from acting

This function answers a question about its inputs:

boolean isWithin(float value, float target, float radius) {
  return abs(value - target) < radius;
}

The radius is assumed to be nonnegative. The strict comparison means a distance exactly equal to the radius is outside. The function returns a boolean; it does not move or draw anything.

Place these calls inside setup() to test it:

println(isWithin(100, 110, 20)); // true: distance 10
println(isWithin(100, 130, 20)); // false: distance 30
println(isWithin(100, 120, 20)); // false: distance exactly 20

The caller can decide what to do with the answer:

if (isWithin(mouseX, 200, 20)) {
  background(0);
} else {
  background(255);
}

This drawing fragment can go inside draw(). The same boolean function can be used elsewhere without forcing the caller to change the background. Separating a check from an action also makes the check easier to test.

8. Functions, loops, and frames

A loop can call a function repeatedly. This complete sketch uses one definition to draw a row of eyes:

void setup() {
  size(500, 250);
  background(200);

  for (int i = 0; i < 5; i++) {
    drawEye(50 + i * 90, 125, 50);
  }
}

void drawEye(float x, float y, float diameter) {
  fill(255);
  ellipse(x, y, diameter, diameter);
  fill(0);
  ellipse(x + diameter * 0.15, y,
          diameter * 0.35, diameter * 0.35);
}

Each call completes before the loop continues. If that loop were inside draw(), all five calls would complete during each frame. Calling a function does not create a new frame.

A function can contain a loop or call another function. Divide the work into tasks whose names communicate their purpose.

For a moving sketch, draw() might express a short sequence of tasks:

void draw() {
  background(255);
  moveSquare();
  drawSquare(sqX, sqY, sqSize);
}

This is an organization example, not a complete sketch: the state variables and the two functions must also be defined. The movement function updates state once per call. The drawing function displays the updated position.

Changing duplicated code into function calls while preserving its behavior is refactoring. Test the original behavior before and after the change.

10. Exercise: The Scared Square

A square moves away when the mouse gets too close. It moves in small steps and remains completely inside the canvas. This exercise separates drawing, checking, and updating state.

Behavior and coordinates

  • Use global variables for the square’s position and size.
  • Use the default CORNER rectangle coordinates: sqX and sqY are its top-left corner.
  • For the required version, check horizontal proximity only. Ignore mouseY.
  • Define proximity using the horizontal distance from mouseX to sqX. Use a strict “less than fearRadius” comparison.
  • Move horizontally away from the mouse in small steps when it is too close. Decide which direction to use when mouseX equals sqX.
  • Keep the whole square inside the canvas. At an edge, staying inside takes priority if it cannot move farther away.

Choose your own colors, appearance, and movement settings. The required functions describe responsibilities, not a complete solution.

Required function headers

void drawSquare(float x, float y, float s) {
  // Draw using these parameters.
}

boolean mouseTooClose(float x, float fearRadius) {
  // Return the result of the horizontal proximity check.
}

void moveSquare() {
  // Use the check, update global state, and enforce boundaries.
}

These are incomplete definitions to implement, not a runnable starter: the boolean function needs a return statement. Inside mouseTooClose(), use the parameter x, not global sqX. This function reads Processing’s mouseX, so its result depends on both the arguments and the current mouse position.

Unlike the earlier isWithin() function, mouseTooClose() is specifically tied to mouse input. It should still return information without moving the square.

Possible starting state

You may use this setup or choose other values. Complete the sketch with draw() and your function definitions.

float sqX, sqY;
float sqSize = 60;
float fearRadius = 20;
float step = 3;

void setup() {
  size(600, 400);
  sqX = width / 2 - sqSize / 2;
  sqY = height / 2 - sqSize / 2;
}

Then use xA = sqX and xB = sqX + 30, keeping a radius of 20, and repeat the comparison. Restore movement after checking the function and remove or limit the debug output.

Write one sentence explaining why mouseTooClose() returns a boolean rather than moving the square itself.

Hints for distance, movement, and boundaries

abs(mouseX - x) gives the horizontal distance. Decide the direction separately by comparing mouseX with sqX. With a top-left position and square size s, the allowed horizontal interval is 0 through width − s.

sqX = constrain(sqX, 0, width - sqSize);

Apply the boundary rule after changing the position. Assume the square is smaller than the canvas and its size is positive. Update the position once per frame; do not use a loop to keep moving until the mouse is far away.

Behavior checks

  • Far from the square: no movement.
  • Near its left side: movement to the right, unless blocked by the edge.
  • Near its right side: movement to the left, unless blocked by the edge.
  • Exactly at the fear radius: no movement under the strict comparison.
  • At both canvas edges: the entire square stays visible.
  • Same mouseX but different mouseY: the required 1D check gives the same result.

Optional: two-dimensional proximity

Extend the check to both coordinates. You can define a rectangular proximity region by requiring both horizontal and vertical distances to be below a threshold; no circular distance formula is required.

Update x and y in directions away from the mouse. Decide what should happen when either coordinate is exactly equal. Keep both coordinates within their allowed bounds. Explain your definition of “too close” and test positions inside, outside, and on its boundary.
