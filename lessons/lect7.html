Loops: making repetition work for you

An if statement decides whether a block runs. A loop can run a block repeatedly. Our first goal is to follow the order of execution and explain why a loop stops.

1. Find what changes

Look at these statements before running them. What stays the same? What changes?

ellipse(40, 100, 20, 20);
ellipse(80, 100, 20, 20);
ellipse(120, 100, 20, 20);
ellipse(160, 100, 20, 20);

The x coordinate changes by 40 each time. We can describe that rule with a variable and a loop. Here is a complete Processing sketch:

void setup() {
  size(300, 200);
  background(255);

  for (int x = 40; x <= 160; x = x + 40) {
    ellipse(x, 100, 20, 20);
  }
}

This sketch creates a static drawing in setup(). There is no need for draw() because nothing needs to change afterward.

2. Read a for loop in execution order

for (initialization; condition; update) {
  // body: statements to repeat
}
  1. Initialize once when execution reaches this loop.
  2. Check the condition. If it is false, leave the loop.
  3. Run the body if the condition is true.
  4. Run the update.
  5. Return to the condition check.

One execution of the body is an iteration. The update happens after the body, even though it is written above the body. This execution order is described in the Processing for reference.

The body runs four times, but the condition is checked five times. x is local to the loop: its name cannot be used after the loop’s closing brace.

3. Predict, explain, then run

For each fragment, list the printed values and the number of iterations. Place each fragment inside setup() when testing.

// A
for (int n = 2; n < 8; n = n + 2) {
  println(n);
}

// B
for (int n = 5; n >= 1; n = n - 2) {
  println(n);
}

// C
for (int n = 4; n < 4; n = n + 1) {
  println(n);
}
Check your reasoning

A: 2, 4, 6 (three iterations). B: 5, 3, 1 (three iterations). C: no output (zero iterations), because the first check is false.

Try it

Change A so that it includes 8. Write a loop that prints 3, 6, 9, 12. Then invent a different sequence with a constant step and exchange it with a partner to trace.

4. Count separately from position

A counter makes “exactly five repetitions” easy to see. A second variable can derive a drawing position from that count. This fragment goes inside setup() after size():

for (int i = 0; i < 5; i++) {
  int x = 30 + i * 45;
  line(x, 50, x, 100);
}

i++ means increase i by 1; here it has the same effect as i = i + 1. The values of i are 0, 1, 2, 3, 4. The positions are 30, 75, 120, 165, 210. The loop counter and the drawing position have different jobs.

Try it

Without running the fragment, predict how many marks would be drawn if i < 5 became i <= 5. Explain why.

Check your reasoning

Six marks: the body runs with i equal to 0 through 5. Starting at zero matters when counting iterations.

5. A conditional inside a loop

A condition can make some iterations different. For this practice, predict the printed words before testing:

for (int i = 0; i < 5; i++) {
  if (i < 2) {
    println("near");
  } else {
    println("far");
  }
}
Check your reasoning

The output is near, near, far, far, far. The condition is evaluated for each iteration, using that iteration’s value of i.

6. Debug by tracing

This programmer wants the numbers 1 through 4. Which part needs to change? Trace on paper; do not run this version.

for (int i = 1; i <= 4; i--) {
  println(i);
}
Check your reasoning

For the intended sequence, change i-- to i++. The shown update moves away from the intended stopping boundary. It will not reach that boundary by counting upward and can flood the console; integer overflow is not a sensible stopping strategy.

7. Your design: repetition with a purpose

Create a visual composition in which repetition contributes to an idea, mood, or recognizable subject. Use a loop to generate repeated elements and a conditional to make some elements different.

Before coding: sketch your idea on paper and describe what repeats, what changes, and why that change matters. Choose the subject and the visual rules yourself.

  • Use a terminating loop to generate the repeated elements.
  • Use a conditional that has a visible effect on some elements.
  • Be able to explain the starting value, condition, update, and number of iterations.
  • Make a deliberate design choice beyond changing a demonstration’s colors.

A static composition in setup() is enough. Animation, grids, media files, and nested loops are optional. Explain the meaning of your rule and show a change you made after testing. Your explanation and control of the code matter more than visual polish.

Questions to help if you are stuck

Where do you notice repetition? What changes across it? Could repetition suggest growth, order, interruption, distance, or movement? Choose one idea and describe its rule in words before choosing coordinates.
