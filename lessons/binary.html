A bit has two possible values: 0 or 1. A sequence of bits can represent a number, but it can also represent other information when we agree on a meaning. In this lesson, number examples use unsigned binary: nonnegative whole numbers.

1. Binary to decimal: positional expansion

Binary is base 2. Number the bit positions from right to left, starting at position 0. The weight of position i is 2i. Multiply each bit by its position weight, then add the products.

For bits bn−1 … b1b0, the decimal value is bn−1 × 2n−1 + … + b1 × 21 + b0 × 20. Each bit is either 0 or 1.

Worked example: 1011012 → decimal

Weight32168421

Contribution3208401

1011012 = 1 × 32 + 0 × 16 + 1 × 8 + 1 × 4 + 0 × 2 + 1 × 1 = 4510.

Zeros contribute nothing to the sum but still occupy positions. Leading zeros do not change the value: 001011012 also represents 45. Subscripts identify the base; without a base, a string such as 101 can be ambiguous.

An alternative: multiply by 2 and add the next bit

Read from left to right, starting with a total of 0. For each bit, multiply the current total by 2 and add that bit. Moving to the next position doubles the value of everything already read.

2. Decimal to binary: repeated division by 2

For a positive whole number:

  1. Divide the number by 2 using integer division.
  2. Record the remainder, which is either 0 or 1.
  3. Use the quotient as the next number to divide.
  4. Continue until the quotient is 0.
  5. Read the remainders from bottom to top. The first remainder is the rightmost bit.

The remainders in calculation order are 1, 0, 1, 1, 0, 1. Reading from the bottom upward gives 1011012. Check by expanding the position weights: 32 + 8 + 4 + 1 = 45.

Why it works: each division expresses the number as 2 × quotient + remainder. The remainder tells us the coefficient of 20, the lowest-weight bit. Dividing the quotient again finds the next bit.

Zero: represent decimal 0 as binary 0. If a fixed width is required, add leading zeros: decimal 45 written in eight bits is 00101101. Do not append zeros on the right; that changes the value.

3. Decimal to binary: subtract powers of 2

This method works from the highest-weight bit toward the lowest. Find the largest power of 2 that does not exceed the number. At that weight and every smaller weight down to 1, write 1 and subtract the weight if it fits in the remainder; otherwise write 0 and keep the remainder.

5. Number of patterns is not the largest value

Each added bit doubles the number of patterns. With four bits, there are 2 × 2 × 2 × 2 = 16 patterns. They represent 0 through 15, because zero uses one pattern.

For n bits: 2n patterns and a largest unsigned value of 2n − 1. Eight bits make one byte. Their weights are 128, 64, 32, 16, 8, 4, 2, 1.

Try it

Can four bits represent decimal 16 as an unsigned number? How many bits do you need? Why can eight bits distinguish 256 possibilities but not represent unsigned 256?

Check your reasoning

Decimal 16 needs five bits: 10000. Eight bits represent 0 through 255. Decimal 256 requires a ninth position: 100000000.

The mathematical result of 1111 + 1 is 10000. If a storage scheme keeps only four bits, it cannot store that full result; a rule is needed for the extra carry. We are not assuming that every language or data type handles that situation the same way.

6. A pattern needs an interpretation

The pattern 0101 represents decimal 5 under unsigned binary place value. Under a different agreed code, it could identify an action, a symbol, or four independent yes/no settings. Its interpretation comes from the rules we assign.

Distinguish a numeric representation from an encoding: the same bits can represent different information under different conventions. The conversion procedures above assume unsigned whole numbers; signed numbers and fractions require additional rules.

7. Connect back to loops

This optional fragment goes inside setup(). Trace its values before running it:

int weight = 1;
for (int position = 0; position < 8; position++) {
  println(weight);
  weight = weight * 2;
}
Check your reasoning

It prints 1, 2, 4, 8, 16, 32, 64, 128: the weights from right to left in an eight-bit number. After the last update, weight is 256, but that value is not printed because the loop ends.
