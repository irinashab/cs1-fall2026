Lesson 11: Images and Pixels

Big idea

An image is a grid of colors. By reading those colors, changing them, and writing them back, we can create our own image filters. We will connect arrays, nested loops, coordinates, and functions.

Core path: map coordinates to array indices, read and write screen pixels, then process an image. After completing the core exercises, choose an extension.

Goals

  • Explain how a two-dimensional pixel grid is stored in a one-dimensional array.
  • Use loadPixels() and updatePixels() with the correct pixel array.
  • Extract RGB components and construct a new color.
  • Keep the source image separate from the output drawn on the canvas.
  • Test a filter with a small example before applying it to every pixel.

Setup: Use Processing in Java mode. All complete sketches below use pixelDensity(1) and the default RGB range, 0–255. This makes each canvas coordinate correspond to one entry in the pixel array, including on high-density displays. Run each complete sketch separately. Code marked as a fragment belongs inside the indicated sketch.

1. One color per array element

The built-in pixels[] array holds the canvas colors. Before reading or changing it, call loadPixels(). After changing it, call updatePixels() to display the changes. Reading alone does not require an update.

Complete sketch:

void setup() {
  size(300, 200);
  pixelDensity(1);
  loadPixels();

  for (int i = 0; i < pixels.length; i++) {
    pixels[i] = color(random(256));
  }

  updatePixels();
}

Each element gets a random grayscale color. The loop runs once during setup(); the picture remains on the canvas.

Predict, then try: Replace color(random(256)) with color(0), then color(255). What changes if you put the pixel-processing loop, with its load and update calls, inside draw()?

2. From a grid to an array

Coordinates and array indices begin at zero. Pixels are stored one row after another. For a grid four pixels wide:

Array indices for a 4 × 3 grid
Row / columnx = 0x = 1x = 2x = 3
y = 00123
y = 14567
y = 2891011

Index formula: loc = x + y * width. Skip y complete rows, then move x positions into the next row. The width must belong to the array you are indexing.

In this lesson, the image and canvas have matching dimensions, so we use width for both. Valid canvas coordinates satisfy 0 <= x < width and 0 <= y < height.

On paper: Find the index of (2, 1) in the table. Then find the coordinates of index 9. Explain each answer.

Check your reasoning

(2, 1) has index 2 + 1 × 4 = 6. Index 9 is at (1, 2). In general, x = loc % width and y = loc / width, using integer division.

Nested loops visit the grid

Complete sketch:

void setup() {
  size(300, 200);
  pixelDensity(1);
  loadPixels();

  for (int y = 0; y < height; y++) {
    for (int x = 0; x < width; x++) {
      int loc = x + y * width;
      if (x % 2 == 0) {
        pixels[loc] = color(255);
      } else {
        pixels[loc] = color(0);
      }
    }
  }

  updatePixels();
}

The outer loop chooses a row; the inner loop visits its columns. The condition creates one-pixel-wide vertical stripes, with column 0 white.

Modify: Make horizontal stripes. Then make vertical bands ten pixels wide. Hint: examine (x / 10) % 2. Predict the colors at x = 9, 10, 19, and 20 before running.

3. Colors and their components

Processing’s color type stores a packed color value. Use helper functions to work with its components rather than treating that value as a brightness number.

Fragment inside a function:

color c = color(180, 60, 30);
float r = red(c);    // 180
float g = green(c);  // 60
float b = blue(c);   // 30

color gray = color(90);            // RGB (90, 90, 90)
color translucent = color(255, 0, 0, 120);

Under the default color mode, RGB components range from 0 to 255. The fourth actual parameter is alpha: 0 is fully transparent and 255 is fully opaque. The last example is partially transparent red. This lesson’s filters use an opaque JPEG image.

color() accepts floating-point component values. brightness(c) extracts HSB brightness; it is not the arithmetic average of the RGB components. For our simple grayscale filter, we will calculate that average explicitly.

A few pixels: get() and set()

color sampled = get(mouseX, mouseY);
set(10, 20, color(255, 0, 0));

This fragment reads a canvas color and writes one red pixel. These calls are convenient for individual pixels and do not require you to manage loadPixels() and updatePixels(). For a whole-image loop, direct array access is generally more efficient.

4. Read an image; write to the canvas

For these examples, the image and canvas have the same width and height. Use a 300 × 168 pixel JPEG named hedgehog.jpeg, or change the numbers in size() to match your image. Add the image using Sketch → Add File so it is in the sketch’s data folder.

We work with two arrays: img.pixels[] stores the image colors, and pixels[] stores the canvas colors. Because their dimensions match, the same index loc identifies the same position in both arrays.

Complete starter sketch:

PImage img;

void setup() {
  size(300, 168);
  pixelDensity(1);
  img = loadImage("hedgehog.jpeg");
}

void draw() {
  loadPixels();
  img.loadPixels();

  for (int y = 0; y < height; y++) {
    for (int x = 0; x < width; x++) {
      int loc = x + y * width;
      color c = img.pixels[loc];
      float r = red(c);
      float g = green(c);
      float b = blue(c);

      pixels[loc] = color(r, g, b);
    }
  }

  updatePixels();
}

loadPixels() prepares the canvas array, and img.loadPixels() prepares the image array. The loop reads an image color, extracts its components, and writes a color to the canvas at the same position. Finally, updatePixels() displays the canvas changes.

This displays the original image. Next, we will change the color before writing it to the canvas.

Trace: With a width of 300, what is loc for (10, 3)? Which array do we read, and which do we change?

Check

loc = 10 + 3 * 300 = 910. We read img.pixels[910] and write to pixels[910]. The original image stays unchanged.

Read → extract → process → write. Each frame reads the original image colors and writes the result to the canvas. This lets us change an effect without overwriting the source image.

5. First filter: grayscale

In the starter sketch’s inner loop, replace the final pixel assignment with this fragment:

float gray = (r + g + b) / 3.0;
pixels[loc] = color(gray);

This simple average gives all three output components the same value. It is a useful introductory grayscale method, though it does not account for differences in human sensitivity to red, green, and blue.

Predict: For RGB (180, 60, 30), calculate the output. Then try a channel swap instead: write color(g, r, b). Explain which components change.

Connect to functions

Move the calculation into a function defined outside setup() and draw():

color toGray(color original) {
  float gray = (red(original) + green(original) + blue(original)) / 3.0;
  return color(gray);
}

Then use pixels[loc] = toGray(c); as the assignment. Identify the formal parameter and the actual parameter. Why does this function return color rather than void?

6. Interactive filter: brighter or darker

The starter already runs every frame. In draw(), before the nested loops, calculate one factor:

float factor = constrain(map(mouseX, 0, width, 0, 2), 0, 2);

Inside the inner loop, after extracting the components, replace the final assignment with:

r = constrain(r * factor, 0, 255);
g = constrain(g * factor, 0, 255);
b = constrain(b * factor, 0, 255);
pixels[loc] = color(r, g, b);

map() converts the mouse position to a factor. constrain() limits a value to the specified range. A factor of 0 produces black, 1 preserves the original components, and 2 doubles them, with values above 255 clipped.

Test on paper: Apply factors 0, 1, and 2 to RGB (180, 60, 30). Then test the mouse near the left edge, center, and right edge. Why must each frame start with the original image colors?

8. Choose an extension

A. Keep colors near a target

Add these global variables above setup():

color target = color(200, 40, 40);
float threshold = 100;

In the starter’s inner loop, replace the final pixel assignment with:

float d = dist(r, g, b, red(target), green(target), blue(target));
if (d > threshold) {
  float gray = (r + g + b) / 3.0;
  pixels[loc] = color(gray);
} else {
  pixels[loc] = color(r, g, b);
}

Here, dist() compares two points in RGB color space, not positions on the canvas. Colors within the threshold, including the boundary, stay colorful. This is an approximate color-similarity rule, not a precise hue classifier. Choose a target found in your image and compare two thresholds.

B. Mirror horizontally

In the starter, read from img.width - 1 - x instead of x, while still writing to screen coordinate (x, y). Derive the source index before coding. Test the leftmost, middle, and rightmost columns. Keep the image and canvas the same size.

C. Flashlight

Calculate the distance from (x, y) to the mouse inside the inner loop. Make the brightness factor decrease as distance increases. Decide on a radius, limit your factor, and test a pixel at the center, at the radius, and outside it.

D. Pointillism

Use sampled image colors to draw circles instead of writing canvas pixels. In a copy of the starter, add img.loadPixels();, background(255);, and noStroke(); at the end of setup(), and replace the entire draw() function with:

void draw() {
  int x = int(random(width));
  int y = int(random(height));
  int loc = x + y * width;
  color c = img.pixels[loc];

  fill(red(c), green(c), blue(c), 100);
  ellipse(x, y, 12, 12);
}

The circles accumulate because the background is cleared only in setup(). We read the already-loaded source array, but draw with ellipse(), so no canvas pixel load/update calls are needed. Explore circle size and the number of circles drawn per frame.

9. Debug and explain

  • Image fails to load: Check the exact filename, extension, and data folder.
  • Array index error: Check the loop bounds, the array’s own width, and pixelDensity(1).
  • Rows appear scrambled: Check that the image and canvas have the same dimensions and that the index is x + y * width.
  • Changes do not appear: Check which array you changed and update the matching image or canvas.
  • Effect becomes stronger every frame: Check whether you are overwriting the source instead of reading its original colors.
  • Pointillist dots disappear: Check whether you are clearing the background every frame.
