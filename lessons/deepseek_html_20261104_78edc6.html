Lesson 9: A Touch of Class

Learning Goals

By the end of this lesson, you will be able to define a simple class, create objects with constructors, and use each object's methods to display it and change its state.

  • Distinguish a class from an object.
  • Identify instance variables, methods, and constructors.
  • Use setup() and draw() to animate independent objects.
  • Design and test a class of your own.

1. Classes and Objects

A class defines a type of object: the data each object stores and the operations it can perform. An object is one particular instance of that class. For example, Ball is a class; firstBall can refer to one Ball object and secondBall to another.

Think of a class as a blueprint and an object as a house built from it: one blueprint can produce many houses, and each house can have its own paint color and furniture.

A class groups two things together:

  • State: instance variables that hold an object's current data, such as its position and speed. Each object gets its own copies.
  • Methods: functions defined inside the class. A method can use the object's state to draw it or change that state.

A constructor supplies the object's initial state when the object is created. The class definition alone does not create or draw any objects.

2. First Complete Sketch: A Simple Constructor

Open a new sketch in Processing Java mode. Copy this entire example into the sketch and run it. Each complete sketch in this lesson runs separately; replace the earlier sketch when trying the next one.

Ball myBall;

void setup() {
  size(600, 400);
  myBall = new Ball();
}

void draw() {
  background(245);
  myBall.move();
  myBall.display();
}

class Ball {
  float x;
  float y;
  float speed;

  Ball() {
    x = 50;
    y = 200;
    speed = 2;
  }

  void move() {
    x += speed;
    if (x > width + 10) {
      x = -10;
    }
  }

  void display() {
    noStroke();
    fill(40, 100, 200);
    ellipse(x, y, 20, 20);   // diameter 20, so radius 10
  }
}

Read the sketch in order

  1. Ball myBall; declares a variable that can refer to a Ball. It does not create the object yet.
  2. setup() runs once. After setting the canvas size, new Ball() creates an object, runs its constructor, and returns a reference stored in myBall.
  3. The constructor initializes that object's x, y, and speed.
  4. draw() repeats. It clears the previous frame, changes the object's position, and draws the object at its new position.

myBall.move() means “call the move method on the object referred to by myBall.” This is dot syntax: object.method(). Inside that method, x and speed belong to that object.

Notice the difference in form: myBall.move() asks one particular object to run its method, while a plain function call like background(245) belongs to the sketch as a whole.

The ball wraps to the left after it passes the right edge. Its radius is 10 pixels, so the boundary check allows the whole ball to leave before resetting it.

Why create the object in setup()? An object created inside draw() on every frame would repeatedly restart at its initial position. Create it once, then update it repeatedly.

Predict, Run, Explain

  • What changes if you set the constructor's speed to 4?
  • What happens if you remove myBall.move()?
  • What happens if you remove background(245) from draw()?

3. Constructors and Methods

A constructor runs when you create an object with new. Its name must exactly match the class name, including capitalization, and it has no return type—not even void. A regular method declares a return type; void means that it returns no value.

Purpose in our sketchInitialize stateUpdate state or display the object
DeclarationBall() { ... }void move() { ... }
Return typeNoneRequired, such as void
How usednew Ball()myBall.move()

We will see a constructor that takes parameters in the next section.

Common errors: void Ball() declares a method instead of a constructor; myBall.Ball() does not create an object; calling myBall.move() before assigning an object to myBall causes an error.

4. A Parameterized Constructor

The first constructor gives every new Ball the same starting values. A parameterized constructor lets the caller choose those values. A parameter is a named input in the constructor declaration; an argument is a value supplied in a call.

In new Ball(50, 120, 2), the arguments become startX, startY, and startSpeed, in that order. The constructor copies them into the object's instance variables. The parameters exist only during the constructor call; the instance variables retain the values afterward.

Second Complete Sketch: Two Independent Objects

Replace your sketch with the following code. Both objects use the same class and methods, but start in different places and move at different speeds. Click the canvas to stop only the first ball.

Ball firstBall;
Ball secondBall;

void setup() {
  size(600, 400);
  firstBall = new Ball(50, 120, 2);
  secondBall = new Ball(300, 280, 4);
}

void draw() {
  background(245);
  firstBall.move();
  firstBall.display();
  secondBall.move();
  secondBall.display();
}

void mousePressed() {
  firstBall.speed = 0;
}

class Ball {
  float x;
  float y;
  float speed;

  Ball(float startX, float startY, float startSpeed) {
    x = startX;
    y = startY;
    speed = startSpeed;
  }

  void move() {
    x += speed;
    if (x > width + 10) {
      x = -10;
    }
  }

  void display() {
    noStroke();
    fill(40, 100, 200);
    ellipse(x, y, 20, 20);
  }
}

This version replaces Ball() with a constructor that requires three arguments. A call to new Ball() will no longer match the constructor in this class.

In fact, Processing will report a compile error such as “The constructor Ball() is undefined.” Here is the precise rule: Java automatically supplies a no-argument constructor only when you define no constructor of your own. Once you write a parameterized constructor, that automatic one no longer exists, so every call to new Ball(...) must pass the required arguments.

Independent State

Each new Ball(...) creates a separate object. Updating firstBall.x or setting firstBall.speed does not change the second object's variables. Both objects still need their own method calls in draw().

By contrast, assigning secondBall = firstBall; would make both variables refer to the same object; it would not make a copy. This statement is an explanation only—do not add it to the two-object sketch.

Direct field access and a look ahead. In mousePressed() we changed firstBall.speed directly from outside the class. That works, but larger programs usually make instance variables private and change them only through methods (for example, a stop() method). Either way, the object's own state stays inside the object; calling a method is just a cleaner way to ask for the change. We will return to private fields later.

Notice the pattern the two methods follow: move() changes x, and display() reads x to draw the ball. Keeping “change” and “draw” in separate methods keeps each one simple and easy to test.

A Note About this

Our parameter names differ from the instance variable names, which makes assignments easy to read. You may also see a constructor use the same names for both. In that case, this.x = x; means “store the parameter x in this object's instance variable x.” You do not need that naming style for this assignment.

  2. Which variables describe each object's state? Which methods change or display that state?
  3. Why does clicking stop only the first ball?
  4. Why do we put creation in setup() and repeated method calls in draw()?
  5. How would you create a third Ball with a different starting position and speed?
Show suggested answers
  1. One class (Ball) is defined; two Ball objects are created (firstBall and secondBall).
  2. Each object's state is x, y, and speed. move() changes x; display() reads the state to draw the ball.
  3. mousePressed() sets only firstBall.speed = 0; it never touches secondBall, whose speed stays 4.
  4. Creating an object once in setup() preserves its state across frames. Repeated calls in draw() then update and redraw that same object instead of restarting it.

Use class names beginning with a capital letter, such as Firefly. Use camelCase for variables and methods, such as glowAmount and updateGlow().

Programming Assignment 9: Design Your Own Class

Create a Processing Java-mode sketch that brings at least two objects of your own simple class to life. Choose something with a visible appearance and a meaningful behavior: a growing plant, a blinking robot, a pulsing star, a filling battery, or another idea you can explain.

Make a design of your own. Merely renaming Ball, changing its color, or replacing the circle with another shape while keeping the same moving-ball design does not meet this assignment. Your state and behavior should reflect your chosen idea. Keep the design small enough to finish and explain.

Part A: Plan Before Coding

Answer these questions in a comment at the top of your sketch:

  1. What does one object represent? What will you name its class?
  2. What three instance variables will each object need? Give each variable's name, type, purpose, and starting value or valid range.
  3. What will the object look like? Include a quick sketch or written description.
  4. What will its behavior method change? How will that change become visible?
  5. Which starting values will your constructor accept? How will your two objects differ?
  6. How will you handle limits, such as maximum growth or brightness? How will you test that the objects are independent?

Part B: Build Your Sketch

  • Define your own class with at least three instance variables that represent meaningful state. Start with three; you may add more if each one is meaningful and you can justify it.
  • Write a parameterized constructor that accepts and initializes all three required instance variables.
  • Write a display method that draws the object using its state.
  • Write at least one separate behavior method that changes an instance variable over time or in response to input. The change must affect what is displayed.
  • Create at least two separate objects of your class using separate new calls in setup(). Give them different arguments so their state or behavior visibly differs.
  • In draw(), clear the background and call the appropriate behavior and display methods for both objects. If behavior depends on input, arrange for each object to be updated when appropriate.
  • Keep each object's changing state inside the object. Use named instance variables rather than separate global variables for each object's state.
  • Use only concepts covered so far. This assignment does not use inheritance.
  • You do not need an array of objects for this assignment; two or three named objects are enough.

Design hint: A plant might store horizontal position, current height, and growth rate. Its display method can calculate the stem and leaves from those values; its behavior method can increase height up to a limit. This is an idea to develop, not a required design or a complete solution.

Skeleton example (not a required design): a tiny class that is clearly not a Ball shows the same structure your assignment needs.

class Firefly {
  float x;           // horizontal position
  float y;           // vertical position
  float glow;        // 0..255 brightness

  Firefly(float startX, float startY, float startGlow) {
    x = startX;
    y = startY;
    glow = startGlow;
  }

  void updateGlow() {
    glow = (glow + 4) % 255;   // pulse, then wrap
  }

  void display() {
    noStroke();
    fill(255, 255, 120, glow);
    ellipse(x, y, 18, 18);
  }
}

Your class should differ from both Ball and Firefly. The point of the example is structure: three meaningful fields, a parameterized constructor, a behavior method that changes state, and a display method that reads it.

Watch out for these common mistakes. Creating the object inside draw() (it restarts every frame); forgetting to call display() after move() or update(); calling a method on a variable that was never assigned with new (a null reference); and putting one object's state in global variables instead of instance variables.

Part C: Test and Explain

  1. Run the sketch from the beginning. Verify that both objects appear with their intended starting values.
  2. Watch or trigger the behavior. Explain which variable changes and how you can see the result.
  3. Change one object's constructor arguments. Confirm that the other object's starting values remain unchanged.
  4. Temporarily comment out the behavior call for one object (for example, // firstBall.move();). Verify that the other object still behaves normally, then restore the line.
  5. Run long enough to reach a boundary or limit. Check that the behavior remains sensible. Test at least one unusual but valid starting value.

Record a short test log in comments: what you tested, what you expected, what happened, and any fix you made. A one-line template you can repeat:

// TEST: changed firstBall startX to 500
// EXPECTED: only firstBall moves; secondBall unchanged
// SAW: secondBall unchanged; firstBall wraps at the right edge
// FIX: none

Finish with two or three sentences explaining how your class organizes state and behavior and how you verified independent objects.

Summary

A class bundles state (instance variables) with behavior (methods), and a constructor sets each object's initial state. Creating objects with new and calling their methods gives you independent, reusable pieces of behavior—the core idea behind this lesson and the foundation for everything that follows.
